# port-net-predict — Known Limitations

- **Campaign co-op: scripted single-target object gives reach the wrong player on the client (e.g. Cassandra's necklace, `setupame.c`).** The necklace is handed out by a *script* (`aiGiveObjectToChr` → `CHR_COOP`), not a proximity pickup. `CHR_BOND`/`CHR_COOP` map to **different physical players on each machine** — on the client the local player is always slot 0 (`netPlayersAllocate` swap) and the host occupies the "coop" slot — so the host gives it to its `CHR_COOP` (= the client, correct, which is why the **objective still completes host-authoritatively and the "Objective Complete" toast shows**), but on the client the same script targets `CHR_COOP` = the *remote host*, so the **local player never gets the item in its own inventory** and the bottom-left "picked up X" toast never fires.
  - **Not mission-blocking:** the gate that the item unlocks (e.g. the basement door) is host-driven — when the host's `CHR_COOP` has the necklace the script sets the stage flag, which is mirrored to the client (`SVC_STAGE_FLAGS`), so the door opens for everyone. Only the client-side inventory entry + pickup toast are missing.
  - **Attempted fixes that don't work** (see `PORT_NET_REVERTED_EXPERIMENTS.md` if expanded): (1) client skips *all* scripted player-gives and relies on the host's `SVC_PROP_PICKUP` — **breaks the spawn loadout**, because spawn gives run before the client is reliably in `CLSTATE_GAME` so the broadcast is dropped (the local give has no such timing dependency); (2) apply the host's echo for non-proximity gives via a syncid-tracked skip-own filter — the necklace lands correctly but the **spawn loadout doubles** (local give + SVC echo), corrupting the ammo counts the mission's "mines wasted" checks read.
  - **Proper fix (TODO, "option 3"):** on the *client*, remap scripted player-give targets (`CHR_BOND`/`CHR_COOP` and any `PROPTYPE_PLAYER` target) to the right local player **by client id** rather than by `g_Vars.bond`/`g_Vars.coop` (which are swapped vs the host). This makes every scripted give target the correct physical player on both machines without needing the SVC echo, so single-target gives (necklace) land locally AND multi-target gives (spawn loadout) don't double. It touches the core co-op player-mapping (`aiGiveObjectToChr`, possibly `chrFindById`/`CHR_BOND`/`CHR_COOP` resolution for player chrs) so it needs its own careful pass with regression testing across every scripted give. Deferred.
- Only Combat Sim (Combat scenario) works reliably; other scenarios broken.
- Cloaking device not synced.
- Slayer fly-by-wire and FarSight alt-fire don't work on clients.
- High bandwidth usage, especially with 8 players; recommend `Net.Server.UpdateFrames=2`.
- Sim bots are position-driven on clients — `SVC_CHR_FIRE` syncs shoot sound + muzzle-flash on/off, and the chr-state block in `SVC_PROP_MOVE` syncs body rotation and animation. `chr->actiontype` is **not** synced (would crash; see Sim Position Sync section); the client always dispatches sim chrTick as `ACT_STAND`, so visible animation comes only from the synced `animnum` and not from any per-action tick logic. Aim/look direction (head/torso) and partial-body animations (limb-specific layers) are still server-authoritative only.
- Punching and a few weapon-animation sounds still play first-person for every listener — the punch swing/hit goes through a code path outside the GUNCMD_PLAYSOUND hook we patched. Source TBD.
- Lag-comp is broad-phase (sphere) only. Narrow-phase bone matrix rewind was attempted and reverted after crashing the host — see Lag Compensation section. A safer narrow-phase pass needs to re-derive matrices on demand instead of writing into the per-frame `gfxAllocate` buffer.
- CSP is back to the simpler retarget-only behavior. At very high ping the local player may drift slightly behind the authoritative position when constantly diverging from the server, but it's stable — no exponential teleporting. Snap branch now uses `chrSetPos` (re-derives ground/rooms + resets `player->vv_manground`/`vv_ground`/`vv_theta`) so snaps actually stick — fixes the previous "client thinks it's standing, server says it's fallen, ack/snap loop forever" desync.
- Pitch-shift effects on remote players' weapon sounds (e.g., mauler charge) are skipped because `psCreate` returns a channel index, not a `struct sndstate *` handle. Local player still gets the effect via `sndStart`.
- Weapon equip / pickup sounds (the ~30 other `sndStart` sites in `bondgun.c`) are still non-positional for remote players. Less audible than fire sounds, so deferred.
- Host spectator mode: no pause-menu UI for per-panel mode/target selection — controls are gamepad-only (C-buttons + Z-trigger + sticks; see netplay CLAUDE.md). A pause-menu submenu is planned as a follow-up.
- Host spectator mode: audio listener still uses the engine's default (active panel via `setCurrentPlayerNum`), but no explicit "follow active panel" selector — 3D sound pan/volume may feel inconsistent when cycling panels rapidly.
- Host spectator mode: when the host's panel is in PLAYER/SIM mode and the target disappears mid-frame, the panel renders the last-known pose for one frame before failing over to freecam. Cosmetic only.
- Host spectator mode: not validated end-to-end (no build env in this workspace) — manual test plan in `~/.claude/plans/wanna-add-a-real-toasty-sketch.md`.
- No build test performed — see "Environment Rules" at the top: this environment can't compile. The user builds externally from MSYS2 MinGW x64.
